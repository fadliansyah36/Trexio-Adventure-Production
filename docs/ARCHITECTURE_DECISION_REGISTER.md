# TREXIO ARCHITECTURE DECISION REGISTER (ADR)

| ADR ID | Date | Architecture Topic | Options Evaluated | Selected Decision | Justification & Benchmark Evidence | Trade-offs & Mitigations | Owner Role | Status |
|---|---|---|---|---|---|---|---|---|
| `ADR-001` | 2026-08-10 | Primary Architecture Pattern | Microservices vs. Modular Monolith | **Modular Monolith** | Current single-instance Express + Supabase PostgreSQL handles 250+ QPS at < 18ms latency with zero network hop overhead | Modular domain boundaries enforced via strict service/repository separation | Tech_Lead | Approved |
| `ADR-002` | 2026-09-29 | Primary Business Database | MongoDB vs. Managed PostgreSQL | **Supabase PostgreSQL** | Relational ACID transactions mandatory for payment ledgers, booking concurrency, and mutual consent privacy | Migration from legacy JSON complete; strict schema drift guard enforced | DBA_ROLE | Approved |
| `ADR-003` | 2026-09-29 | Identity & Authentication | Custom JWT vs. Firebase Auth vs. Supabase Auth | **Supabase Auth** | Battle-tested OAuth 2.0 / OpenID Connect integration for Google Login; mapped to `users.uid` in PostgreSQL | Decouples password/auth key storage from primary database | Security_Role | Approved |
| `ADR-004` | 2026-08-10 | Caching Layer | Redis Cluster vs. In-Process Caching | **In-Process Caching & CDN** | PostgreSQL query response time < 15ms with composite indexes; Redis introduces unneeded network complexity | Re-evaluate if database QPS exceeds 2,500 | Backend_Role | Approved |
| `ADR-005` | 2026-08-10 | Asynchronous Background Processing | Kafka vs. RabbitMQ vs. Async Workers | **Async In-Process Job Queue** | Notifications, emails, and audit logs decoupled via async workers without external message broker overhead | Failure handling relies on PostgreSQL transactional retry state | Backend_Role | Approved |
| `ADR-006` | 2026-08-10 | Contact Privacy Enforcer | Client-side hide vs. Server-side RBAC | **Server-side RBAC & Mutual Consent** | Contact info (`phone`, `email`) hidden at API layer until explicit mutual consent is recorded in `travel_intents` | AI matching recommendations strictly pre-filtered before contact unlock | Security_Role | Approved |
